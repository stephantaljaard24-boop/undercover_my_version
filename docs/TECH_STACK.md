# Tech stack

- `backend/`: FastAPI and SQLite, in layers: `main.py` builds the app, `routes/` has the routes by resource, `rules.py` the status and sign-off rules, `store.py` all the SQL. It also serves the wording and the manual by section, and keeps each run and its to-do list. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount.
- `agent/`: LangChain's `create_agent` on OpenRouter, with no other agent framework. A queue agent runs the whole queue from a to-do list and hands each claim to a claim agent that works it from a clean start. Two entry points: a queue run, with an optional cap on claims, and a single claim, which takes a claim id. Retries and call limits are LangChain middleware. It uses `deepseek/deepseek-v4.1-flash` with low reasoning effort by default, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`. Its layout: `harness/` runs any agent (the model, the middleware, running an agent and streaming its steps, the to-do list tool, a run's cap and lock) and knows nothing about claims; `undercover/` is the business (the one client for the backend, the claim tools, the claim agent and the queue agent); `__main__.py` is the entry point. Imports point one way, entry point to `undercover` to `harness`, and a test checks it. The agent reaches claims, the wording, the manual and its instructions only through the backend's API, in `undercover/backend.py` and nowhere else.
- `dashboard/`: React, Vite and TypeScript.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. The OpenRouter key is `OPENROUTER_API_KEY` in `.env`.
